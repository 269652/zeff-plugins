# Jira (jira-ext)

The port of Zeff's built-in Jira — stage 3 of docs/plugins/jira-port-plan.md: **reading**. Generated by Zeff's `scripts/port-jira.mts`.

- **The reader** is the driver lambda `jira.driver`: it starts the Jira MCP server the plugin's settings name (`mcp-atlassian`) and, in one
  session, reads your tickets, the chosen boards' issues (paged) and the titles of booked tickets — normalized with the built-in's own core
  (`src/lib/jira/normalize.ts`, bundled in `lambdas/_lib.mjs`). **When Jira or its server changes and the sync breaks**, mend it in the
  Studio (Lambdas → jira.driver) — you or the AI; the fix is kept in Zeff's database. It runs a program on this computer, so the plugin asks for `exec`.
- **The sync** is the flow `jira.sync` — a step of the Sync menu in the built-in's place: the kernel's `jira.settings` (which boards, which booked
  tickets lack a title) → the reader → the kernel's `jira.keep` (the tickets upserted, their boards, which are yours, titles; then the boards'
  databases and the pipelines). A board not read to the end deactivates nothing.
- **The settings** (Plugins → Jira): the server's command, arguments and environment (the token — encrypted), the address, the search tool, your
  JQL. They are carried over from where Zeff had them when you switch; the token is never shown.
- **Still Zeff's** (next stages): changing Jira — transitions, comments, new tickets — and writing context and notes into Jira.

**Switching:** Plugins → Jira (built-in) → *Switch to the plugin*.
